## Reporting a vulnerability

**Do not open a public issue.** GitHub private vulnerability reporting is enabled on the repository: open a [new report](https://github.com/getmikan/Citrus/security/advisories/new) on the Security tab. Only the maintainers see it, and the discussion and the fix happen in a private advisory.

To help us move quickly, include:

- the Citrus version or commit and the platform;
- the affected component (a protocol, a listener, the controller, the updater and so on);
- a minimal config and the steps to reproduce;
- what an attacker can do and what access they need.

We acknowledge the report, fix it on a private branch, publish the fix and the advisory, and credit the reporter if they wish. The same rules are in [SECURITY.md](https://github.com/getmikan/Citrus/blob/dev/SECURITY.md).

Send issues in the forks [getmikan/utls](https://github.com/getmikan/utls), [getmikan/tls](https://github.com/getmikan/tls) and [getmikan/http](https://github.com/getmikan/http) here as well. If the problem also exists in mihomo, say so in the report.

## Supported versions

Fixes land on `dev`, then in `main` and in releases. There are no maintenance branches for older versions: update to the latest build.

## What has been done

Citrus has been through a security review, an internal code review of the core and of the utls fork, and a static audit. Every finding was fixed in its own pull request, each with a test that fails on the old code. The PRs are listed in the [changelog](/Citrus/en/changelog/#hardening).

### Controller

- Without a `secret` the controller does not listen on a network address; on loopback without a secret it refuses browser requests from other sites and DNS rebinding.
- The unix socket and the named pipe are owner-only; the `secret` is checked on every listener, `/debug` included.
- A changed `secret` takes effect at once and closes open streams; connections are bounded in header time and idle time.
- The API does not return inbound passwords and keys, and `external-ui` cannot point at the folder that holds the config and keys.

### Authentication on inbounds

- The HTTP proxy authenticates every request, not only the first one on a connection.
- UDP through SOCKS5 works only with an open association, bound to its user and port.
- Changing a user's password or removing the user closes its sessions; empty user names are refused.
- UDP sessions are keyed by inbound and user, so one user's rules and limits never apply to another.
- A client address from proxy headers is accepted only from the listed `trusted-proxies`.

### Pre-authentication resources

- Every inbound has a handshake deadline: a client that has not sent its credentials within 15 seconds is dropped.
- State a client can create before its credentials are checked (XHTTP sessions, 0-RTT tickets, QUIC streams, multiplexed streams, fragment reassembly) is bounded in count, size and time.
- Lengths declared by the peer are checked before memory is allocated.

### Downloads and files

- Provider responses, geodata, UI archives and update packages are bounded in size, and archives in entry count.
- Paths are checked with symlinks resolved, and provider files are written atomically.
- A public URL cannot redirect a download into the internal network.
- New config, provider and cache files are created owner-only.

### TLS and updates

- TLS 1.2 minimum on every TLS inbound and on the controller.
- The forks [getmikan/tls](https://github.com/getmikan/tls) and [getmikan/utls](https://github.com/getmikan/utls) carry the crypto/tls security fixes from Go 1.26 (ECH outer extension validation, CVE-2026-97031, and a KeyUpdate bound).
- Self-update checks the package against the release's `checksums.txt` and picks the file name itself instead of trusting names inside the archive.

### Build and CI

- Every GitHub Action is pinned to a commit SHA, and the Docker base images and test images by digest; updates come in through Dependabot.
- CI tokens get the least privilege: read-only for the build, only the needed scopes for publishing releases and images.
- CodeQL, govulncheck, dependency review, `go vet` and a `go mod tidy` check run on every PR.
- The Xray and mihomo binaries used by the interop tests are checked against a pinned SHA-256.
