The full reference is [`docs/config.yaml`](https://github.com/getmikan/Citrus/blob/main/docs/config.yaml) in the repository: every key with example values. Its comments are still mostly in Chinese, as upstream.

The config format is shared with mihomo, so the [mihomo documentation](https://wiki.metacubex.one/) on keys and the controller API applies too.

## Sections

| Keys | What they set |
| --- | --- |
| `mixed-port`, `port`, `socks-port`, `redir-port`, `tproxy-port` | Local proxy ports. |
| `allow-lan`, `bind-address`, `authentication`, `lan-allowed-ips` | LAN access and authentication. |
| `mode`, `log-level`, `ipv6`, `find-process-mode` | General behaviour. |
| `log-format`, `log-timestamp-format` | Log format: `text` (the default) or `json`, one object per line for Loki and ELK. |
| `tcp-concurrent`, `tcp-connect-timeout` | Outbound TCP dialing: race all resolved IPs; total connect budget in milliseconds (default 5000, range 100–600000). |
| `external-controller`, `external-ui`, `secret` | The controller API and web UI; a network address needs a `secret`, see [Controller security](/Citrus/en/start/controller/). |
| `user-stats` | Per-user traffic accounting for inbounds (on by default), see [User traffic](/Citrus/en/start/user-stats/). |
| `user-limits` | Limits of inbound users: speed, connections, addresses, quota, expiry, see [User limits](/Citrus/en/start/user-limits/). |
| `metrics`, `health-without-auth` | Prometheus metrics (`GET /metrics`) and the `/healthz`, `/readyz` probes, see [Metrics and health](/Citrus/en/start/metrics/). |
| `tun` | The TUN device and network stack. |
| `dns`, `hosts` | DNS servers (DNSCrypt v2 `sdns://` stamps included), fake IP, policies for DNS queries. |
| `dns.serve-expired`, `dns.serve-expired-ttl`, `dns.serve-expired-client-timeout` | Serving expired cache entries while they refresh (RFC 8767). By default an expired entry is answered at once and refreshed in the background, as before; a TTL and client timeout give RFC 8767 behaviour. |
| `sniffer` | Domain detection from traffic (TLS, HTTP, QUIC) and BitTorrent detection for the `PROTOCOL` rule; `skip-threshold` sets after how many failures a destination is no longer sniffed. |
| `proxies`, `proxy-groups`, `proxy-providers` | Outbound proxies, selection groups and remote proxy sets; `type: chain` groups for cascades, see [Chains](/Citrus/en/start/chains/). |
| `rules`, `sub-rules`, `rule-providers` | Routing rules and remote rule sets. |
| `listeners`, `tunnels` | Extra inbounds, including server protocols. TCP listeners can listen on a unix socket: `listen: unix:/path`, with the mode set by `unix-mode`. They also take `proxy-protocol: true`: every TCP connection must then start with a PROXY protocol v1 or v2 header, whose client address becomes the source address (logs, rules, per-user IP limits). Only the peers in `proxy-protocol-trusted` (loopback by default) may send it; anything else is closed. UDP is not affected. |
| `geox-url`, `geo-auto-update` | Where and how often to update geodata. |

## Rules at runtime

`PUT /rules` with the body `{"rules": ["DOMAIN,a.com,DIRECT", "MATCH,PROXY"]}` replaces the top level rules without a config reload. The lines are written as in `rules:` and parsed by the same code: targets are proxies and groups, and `RULE-SET`, `SUB-RULE` and logic rules work. The whole list is validated before the swap; a bad line gives 400 with the error and leaves the rules unchanged. Proxies of `proxy-providers` cannot be targets (as in the config): use a group. `sub-rules` and `rule-providers` stay as they are.

The replacement lives in memory only: the next config reload (`PUT /configs`, `systemctl reload`, a restart) brings back the rules of the file. The response is `{"count": N, "ephemeral": true}`.

## Testing

```bash
citrus -t -f ~/.config/citrus/config.yaml
```

The command parses the config and exits without starting anything. The packaged service re-reads the config on `systemctl reload citrus`.

## Reloading

`PUT /configs` (with or without `force=true`) and `systemctl reload citrus` apply the access policy of the new config at once: `allow-lan`, `bind-address`, `skip-auth-prefixes`, `lan-allowed-ips`, `lan-disallowed-ips`, `authentication`, the built-in `ss-config` and `tuic-server`. Without `force=true` the built-in `port`, `socks-port`, `redir-port`, `tproxy-port` and `mixed-port` listeners keep the ports they run on (a client may have changed them with `PATCH /configs`); they are rebound when `allow-lan` or `bind-address` changed.
